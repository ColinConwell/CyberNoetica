# Journey: composable, audio-guided transitions

Implemented September 13, 2026. Individual remains the startup mode and the existing catalog still has 72 visualizers. Journey is a separate runtime mode; it does not add a catalog entry or replace the native implementations.

## Delivered behavior

- Visual now opens with five expandable catalog clusters. Search, list view, selection and variant labels remain available. Individual / Journey sits inside the existing glass panel and four-button layout.
- Journey supports Orbital α, Lissajous, Harmonograph, Spirograph, Rose Curve, Lorenz, Rössler, Chen, Torus Knot and Icosahedral Sphere. Other entries are identified as Individual-only while their adapters are unavailable.
- Character retains native rendering during holds, with short composited handoffs around geometric transport. Unified uses instanced particles and short tangent ribbons. Ribbons represent local curve direction; they never connect unrelated transported sample IDs. Style changes keep the active route position.
- Routes default to six reproducible stops, avoiding adjacent repeats, with 16-second holds and 4-second morphs. The editor supports add/remove, drag and button reordering, per-stop timing, looping, seed-based generation and local JSON import/export. Version 1 data is validated and persisted separately from normal preferences. Progress updates do not replace the editor DOM.
- Independent Journey pause leaves audio running; global pause freezes timing. No Audio uses an autonomous clock. Next, retry and skip are available. A failed preparation leaves the existing endpoint visible.
- Stops can contain up to three ordered layers, with opacity and transforms, or up to three contributors to an approximate displacement blend. Weights are normalized and smoothed; an all-zero edit retains the previous distribution. Mappings to the initial reference contributor stay fixed while weights change. The editor reveals these controls on request.
- File playback retains its decoded buffer and has separate media position, duration and seek APIs. `getCurrentTime()` retains its original AudioContext/analysis-clock meaning. Source generation checks prevent stale decodes from replacing a newer source, and node-identity checks discard pre-seek completion callbacks. Seeking affects the committed file; a separately pending source selection retains its transaction.
- File analysis streams acknowledged PCM chunks to a cancellable worker, retaining energy, novelty, onset/beat positions and suggested energy/change cues. Tempo uses autocorrelation and a dynamic-programming beat sequence. The timeline exposes seeking and editable cues, estimated BPM, manual BPM, half/double tempo and offset. Labels describe estimates and landmarks, not verses, choruses or downbeats. Soundscape provides its known tempo; live sources support onset/duration timing and manual/tap tempo.
- Seeking resolves the destination segment directly from durations or the selected musical marker grid. It prepares deterministic geometry, then hands over briefly instead of replaying missed events. Hidden tabs cancel pending visual preparation and reconcile the file position on return. Context restoration rebuilds the active route segment and preserves independent pause/style/view.
- Soundscape synthesis now has a dedicated engine. The four original macros and default sound remain; progressive controls expose three voices, noise, amplitude/filter envelopes, resonant filters, two LFOs, eight modulation routes, synchronized delay and output. Its original tempo pulse remains part of the macro sound. Audio-clock curves interpolate modulation at audio rate from 320 Hz knots, and parameter edits smooth over 50 ms. Envelopes/LFOs are also signal providers. Analysis remains before speaker mute, with separate analysis gain.

## Geometry and correspondence

`ComponentFrame` adapters borrow actual particle, curve and surface buffers from the native models. Torus Knot evaluates its native shader's center/normal/radius deformation. Sphere samples use the actual mesh and object transform. Curves and RK4 flows reuse `SegmentBatch`. Camera projection maps each model to normalized screen coordinates, retaining native aspect and framing.

Curve and surface slots are initialized by arc length and triangle area. Their primitive identities and local coordinates remain fixed while the underlying geometry evolves; this intentionally avoids recomputing a changing assignment every frame. Particle slots track original particle IDs, including lifetime fades. Topology revisions fade down before rebuilding sampling slots, then fade up. Sampling structures are reused; completed transport maps are not reused across different endpoint states.

The baseline evaluates seven deterministic projection-sort assignments. It is complete and bijective. A worker builds at most 25 candidate edges per sample from nearby axis ranks plus every baseline edge, runs log-domain sparse Sinkhorn (up to 48 iterations / 180 ms refinement budget), and rounds with bounded improving permutation swaps. Refinement is accepted only with finite residuals, a complete assignment and lower measured geometric cost. A timeout after delivery of the baseline uses that baseline. This is an approximate correspondence method, not exact OT or a multi-marginal solver. It avoids barycentric endpoint contraction. Dense transport's quadratic memory requirements are discussed in the [POT numerical guide](https://pythonot.github.io/master/user_guide.html).

GPU interpolation uses quintic easing and a displacement envelope with zero value and first derivative at both endpoints. Audio guidance is a provider of generic timestamped signals, with bounded amount/range/inversion/smoothing controls. Raw onset timing is published separately from flash-suppressed visual features.

The solver owns one active job and one replaceable pending job. Endpoint preload and transport preparation occur outside rendering. Journey owns its endpoint buses, scenes, cameras, adapters and render targets; cancellation and session generations guard asynchronous completion. SceneManager retains one render loop and measures the entire rendering delegate. Adaptive budgets are 2,048 / 4,096 / 8,192 total samples, shared between endpoints and among contributors; budget changes prepare a replacement at a hold boundary. Native model buffers remain independently owned.

The beat tracker uses the autocorrelation / dynamic-programming formulation described by [Ellis (2007)](https://www.ee.columbia.edu/~dpwe/pubs/Ellis07-beattrack.pdf); this implementation has a simplified tempo prior and bounded lag neighborhood, and does not claim an exact reproduction of the reference implementation.

## Running the gates

```sh
pnpm test
pnpm typecheck
pnpm build
pnpm dev --host 127.0.0.1
pnpm test:e2e
pnpm test:journey
pnpm test:catalog
node scripts/run-journey-qa.mjs --endurance
node scripts/run-journey-qa.mjs --benchmark
node scripts/run-journey-qa.mjs --benchmark --unified --high
```

`JOURNEY_QA_URL` points the browser runners to another local server. `PLAYWRIGHT_CHANNEL` chooses an installed browser channel (Chrome by default). QA builds use `CYBER_QA=1`; ordinary production builds do not expose QA entries.

## Limits and remaining hardware qualification

- Hardware timing gates still need a recorded integrated-GPU laptop and physical mobile devices. Chrome's mobile viewport validates controls and layout, not a phone GPU. Other browser engines need separate coverage.
- File beats/onsets/cues are estimates. Overrides intentionally replace an estimated tempo grid with a uniform manual grid. Seeking resumes seeded prepared model geometry, not a reconstruction of every historical nonlinear simulation frame.
- Sample density is area/arc-length weighted at preparation and remains attached to primitives during deformation. Strong deformation can change instantaneous density. Topology changes use bounded fades instead of continuously solving a new map.
- Character uses the shared geometric renderer for multi-model displacement-blended holds, since a weighted geometry has no single native shader. Layered holds retain native component rendering.
- Full shader-field/fractal adapters and WebGPU compute remain later extensions. No MIDI/keyboard instrument, polyphony, two-deck mixing or pitch-preserving time stretching was introduced.
