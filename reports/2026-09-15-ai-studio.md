# AI studio — 2026-09-15

## Delivered

Open **AI studio** from the top-left launcher, the Developer workbench, or the Control panel. Enable assistants, select **Debug & improve** or **Create a visualizer**, and send a request. OpenAI / `gpt-6-astra` is the default. Model identifiers remain editable.

The studio supplies current control bounds and configuration to a tool-using agent. Tools inspect state, search control metadata, validate active controls, sample measured CPU/GPU work, tune individual visualizer parameters/views, change active Soundscape macros/patches or Journey definitions, select menu layouts, and record source-edit handoffs. Local development additionally offers allowlisted source excerpts and two fixed test suites. Tool results are collapsible; model text and tool output are rendered as text.

Live edits are staged behind **Apply proposed edit** unless **Allow live edits** is selected. Each request has a six-round limit, Stop, explicit tool errors, and a single **Undo last live edit**. Parameter/source/route/menu fingerprints reject stale proposals and stale undo requests. Undoing creation restores the prior model's tuned controls and camera; Journey undo restarts its configuration rather than reproducing transport time. Changing connection settings clears conversation context. Disabling assistants clears the key and resets live-edit permission.

Source edits, default promotion, arbitrary scripts, deployments and unrestricted renderer implementations are recorded for handoff. Handoffs include the existing workbench's scoped annotations and versioned configuration. An agent cannot silently write source defaults.

## Provider integration and credentials

The user explicitly authorized AI-provider keys from the repository's `.env.local`. In Vite development, the router reads only its allowlisted provider key names from that file at server startup. Values are not returned in config, included in recorded state, or bundled into browser assets. The UI reports key availability only. A typed session key overrides the local key.

The built Express server and Vite preview use BYOK only, even if provider keys exist in the server environment. Assistants start disabled. Once enabled, the password field accepts a session-only key; it travels via the same-origin server to the selected provider and is not written to browser storage. The production route sits behind the existing site authentication gate. Production source and test endpoints return 404.

Cursor is presented separately because its API starts repository work rather than editing the current browser scene. The user supplies repository, starting branch and handoff request, then explicitly launches it. Launch disables automatic pull requests and direct work on the starting branch. No remote Cursor task was created during validation.

Requests use fixed provider endpoints, reject redirects, cap JSON/history/tool sizes, time out, and enforce rate/concurrency limits. Development requests require a loopback connection and local host; mutations require a same-origin request and the enabled-studio header. Fixed local test scripts receive a small environment allowlist. Provider error messages omit raw upstream bodies. API costs still depend on the chosen model and conversation size; the six-round cap is not a monetary budget.

## Creating visualizers

Creation mode builds version-1 declarative recipes with orbit, rose, helix, Lissajous and wave layers; line or point rendering; palette, movement and audio-response values. Validation caps recipes at six layers and 12,000 samples and rejects executable or unknown fields. Generated JavaScript, GLSL, network URLs and shell commands are not evaluated.

A recipe registers as a normal individual visualizer, uses the existing scene/camera/disposal lifecycle and appears in **Studio creations** in the Visual menu. The gallery provides preview, local recipe saving, JSON export and validated import. Saved recipes restore on reload. The workbench and agent can tune the new model's declared live controls. Local source navigation for a creation resolves to the recipe renderer.

The live Astra browser check generated **Silver Tide**, attached it, and ran `validate_controls` successfully. A follow-up in Debug mode set Motion speed to exactly 0.5; undo restored 1. Browser tests separately verified recipe geometry rendering, save/reload/selection, and resource disposal in unit tests.

## Limits

- Creation is a bounded procedural grammar, not arbitrary new shader or simulation code. Generated models currently have no Journey transition adapter. Model quality, composition and framing vary with the prompt.
- **Save locally / Export recipe** preserves the recipe. Subsequent live control tweaks belong in **Record state** or an agent handoff; they do not rewrite the saved recipe. The gallery is capped at 16 creations per session.
- Search remains local synonym/token matching. The chat agent adds natural-language reasoning but does not supply an embedding index.
- Configuration fingerprints omit animated camera coordinates; they are not a general concurrency transaction for every internal simulation field. Stop prevents subsequent tool dispatch; edits already applied remain applied. Undo is one edit, not a full history.
- Exact audio, GPU buffers, random history and Journey transport are not replayed. Performance sampling is diagnostic, not a benchmark. Source lookup points to declared modules/shared recipe code, not a generated primitive's individual source line.
- Fixed test tools are development-only. Browser/MCP tools, arbitrary network lookups and arbitrary shell execution are not exposed to the in-app agent.
- Physical devices, non-Chromium engines, live Cursor task launch and a direct Kimi account remain untested. No deployment, commit or push was performed.
